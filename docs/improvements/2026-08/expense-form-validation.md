# 거래 입력 검증 및 복귀 흐름 개선

> 작업일: 2026-08-20

## 문제

- 기존 동작: 금액·날짜 검증이 제한적이고 저장 성공 안내 직후 화면이 이동했다.
- 문제점: 존재하지 않는 날짜, 미래 날짜, 중복 저장, 입력 화면 재진입 시 이전 상태 잔존 가능성이 있었다.
- 사용자 영향: 잘못된 날짜의 거래나 중복 거래를 저장하거나 새 입력에 이전 값이 남을 수 있었다.

## 원인

- 원인: 날짜 형식만 부분적으로 확인하고 저장 진행 상태와 신규 입력 세션을 구분하지 않았다.
- 관련 파일/API/DB: `ExpenseFormScreen.tsx`, `ExpenseScreen.tsx`, `Button.tsx`, `POST/PUT /expenses/`

## 수정

- 변경 내용: 입력값 검증, 저장 상태, 신규 입력 초기화, 저장 후 이동 시점을 보완했다.
- 변경 파일: `ExpenseFormScreen.tsx`, `ExpenseScreen.tsx`, `Button.tsx`, `api.ts`, `expenses.py`
- 주요 로직 변경:
  - 제목 공백과 1원 미만·정수가 아닌 금액 거부
  - 연·월·일을 다시 비교해 존재하지 않는 날짜 거부
  - Frontend와 Backend 모두 미래 날짜 거부
  - 저장 중 버튼 비활성화
  - `formSessionId`로 신규 입력 상태 초기화
  - Backend 422 상세 메시지를 사용자에게 표시
  - 성공 안내의 확인 버튼을 누른 뒤 선택 월 장부로 이동
